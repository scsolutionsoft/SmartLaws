# Case appointments

## Appointment documents

The appointment detail dialog now includes supporting documents and a jump button. Saved appointments can link existing case files, link saved Studio documents, create a Studio document and save/link it, or upload multiple PDFs/PNGs/JPEGs (10 MB each). New appointments must be saved first. `SL_AppointmentFiles` stores many-to-many references; files remain in the existing case catalogue. Linking a Studio document reuses its COURT_FORM entry or creates one, and shows the current saved document rather than a frozen PDF snapshot. For a fixed filed version, upload the final PDF.

The catalogue displays appointment names/dates as backlinks. Unlinking preserves the file, and deleting an appointment removes only its links. Files/documents still linked to appointments cannot be deleted; linked appointments/documents cannot move to another case. All attachment endpoints validate case access and require matching case IDs. Sequential uploads retain saved file IDs when linking fails so retry does not duplicate the file. Existing file signature/type validation applies. The normal Studio save remains available; the appointment banner provides the explicit Save and link action.

`scripts/appointment-files-smoke.mjs` verifies Studio creation, repeated link deduplication, PDF/image upload, a failed link and retry, catalogue backlinks, protected file/document deletion, unlink preserving content, and unauthorized access. It uses the same browser/session environment variables as the calendar smoke test and cleans up its fixtures.

The calendar stores multiple appointments per case in SQL Server (`SL_Appointments`). Startup creates the table and case/date index. Existing NextHearingDate values remain visible as time-unspecified entries. Editing opens a popup requiring explicit start/end times. Saving atomically creates a calendar appointment and clears the original case hearing date/note, guarded by the original date/note snapshot (409 on stale requests). Canceling does not migrate anything. Lawyers can also delete the original hearing via the table. Both operations enforce case scope.

Lawyers and assigned clerks can create/edit appointments in their accessible cases. Only lawyers can permanently delete them. Use cancelled status to preserve history. Admin accounts do not access case appointments. Every read is scoped in SQL, and mutations validate case access on the server. Audit logging uses the existing API filter. Version checks reject concurrent edits with HTTP 409.

Date/time inputs and displays use Asia/Bangkok (UTC+7); SQL stores datetimeoffset values. End must follow start, maximum duration seven days. Date-range searches are bounded to one year. Appointment types, statuses, lengths, and reminder ranges are validated by the API. Overlapping appointments in accessible cases produce an advisory in the editor, allowing different responsible people to attend simultaneously.

Monthly calendar and searchable table show title, type, location, black/red case numbers, parties, responsible person and status. Search normalizes Thai digits. Monthly print opens a separate landscape A4 document, includes all statuses and is independent of the court-form print pipeline. Use its Print / Save PDF button.

Dashboard and in-app reminders refresh on entry, every minute while the page is visible, and when returning to the tab. Notifications cover configured advance time (up to 30 days), the appointment day, and unfinished appointments from the last seven days. Completed/cancelled entries do not notify. Acknowledgment and 15-minute snooze are stored per account/event/version in this browser; another device maintains its own acknowledgment state. Editing an appointment allows a fresh reminder. This is not background push, email or SMS: no popup is delivered while the application/browser is closed. Legacy time-unspecified appointments notify on their date rather than claiming a precise hearing time.

Validation: `scripts/calendar-smoke.mjs` runs against localhost:5088 and Chrome CDP :9222 with SMARTLAWS_LAWYER, SMARTLAWS_LAWYER_PASSWORD, SMARTLAWS_OTHER_LAWYER and SMARTLAWS_OTHER_PASSWORD. It checks persisted create/edit, optimistic concurrency, invalid intervals/ranges, unauthenticated and cross-lawyer access, escaped titles, search, monthly print document, dashboard, popup/snooze, and mobile bounds. Temporary appointments are deleted afterward. The earlier 800-account/200-user capacity report predates this feature; it is not a load test of appointment polling.

Deployment: publish includes the module and migration code, not SQL data. Retain the existing database to preserve restored PDFs and appointments. The deployment database account needs schema creation permission for first startup (or have the administrator apply the migration first).

The table exposes Edit, Documents / Add documents, and lawyer-only Delete actions. Documents open a second modal with title, case numbers, storage date, type, status, page count, uploader and remarks, plus an open-reader button. Deleting an appointment preserves catalogue files. appointment-actions-smoke.mjs checks the legacy editor and stale/unauthorized legacy mutations; appointment-files-smoke.mjs also checks document detail modals and table actions.

Appointment dates now use Thai month names and Buddhist Era year selectors, including month/range filters and start/end times. The visible controls use 24-hour time; hidden values retain ISO Gregorian dates for APIs and UTC+7 conversion. Invalid day selections clamp to the last valid day when changing month/year. Tests: appointment-thai-dates-smoke.mjs (Thai labels, leap years, ISO conversion, required fields), plus the calendar regression suite.
