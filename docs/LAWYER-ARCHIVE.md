# สำรอง ลบ และกู้คืนทนาย (เฉพาะแอดมิน)

เมนูผู้ดูแล → สมาชิก → **สำรอง / ลบข้อมูล** เฉพาะสมาชิกบทบาท Lawyer

1. ตรวจจำนวนคดี ไฟล์ เอกสาร วันนัด ลูกความ และเอกสารส่วนตัว
2. ดาวน์โหลด ZIP และตรวจว่าได้รับไฟล์จริง (เบราว์เซอร์ไม่สามารถยืนยันการบันทึกลงดิสก์แทนผู้ใช้)
3. เลือกช่องยืนยันและพิมพ์ `ลบทนายและคดีทั้งหมด` ก่อนลบถาวร

เซิร์ฟเวอร์กำหนดหลักฐานดาวน์โหลดอายุ 30 นาที ผูกกับแอดมินและบัญชีทนาย ตรวจ fingerprint ข้อมูลใหม่ในธุรกรรมเดียวกับการลบ หากข้อมูลเปลี่ยนต้องสำรองใหม่ ยกเลิกเซสชันทนายและลบเฉพาะคดีของทนาย บัญชีลูกความและคดีของทนายอื่นยังอยู่ ลายเซ็นแบบเดิมที่ระบุเจ้าของด้วยชื่อและมีชื่อซ้ำกับสมาชิกอื่นจะคงไว้เพื่อไม่ลบข้อมูลร่วม

## ข้อมูลใน ZIP

`lawyer-data.json` รวมประวัติทนาย ข้อมูลบัญชีที่ไม่ใช่รหัสผ่าน คดี คู่ความ เอกสารสตูดิโอและภาพลายเซ็น วันนัด ขั้นตอนคดี ความสัมพันธ์ไฟล์ เอกสารลูกความ สิทธิ์และประวัติแชท เอกสารส่วนตัว ประวัติสลิปชำระเงิน ข้อความติดต่อแอดมินและการมอบหมายเสมียน ส่วนไฟล์ต้นฉบับจากดิสก์รวมแยกไว้ใน `files/` ภายใน ZIP

ลิงก์ภายนอกเก็บ URL ไม่ดาวน์โหลดเนื้อหาจากเว็บไซต์อื่น ไม่รวมเซสชัน รหัสผ่าน หรือ password hash บันทึกการตรวจสอบระบบ (audit) คงอยู่ฝั่งเซิร์ฟเวอร์

`signature.txt` เป็นลายเซ็นตรวจความถูกต้องด้วย ASP.NET Data Protection และ `README.txt` อธิบายการใช้ไฟล์ ZIP สำหรับทนายนี้เป็นคนละรูปแบบกับ ZIP รายคดี

**ต้องเก็บ Data Protection key ring เดิมของระบบไว้ด้วย** ไฟล์กู้คืนได้ในระบบเดิมหรือการติดตั้งที่ใช้ key ring และ application discriminator เดิม การหมุนคีย์ตามปกติยังอ่านคีย์เก่าได้ แต่หากลบคีย์หรือย้ายเซิร์ฟเวอร์โดยไม่ย้ายคีย์จะตรวจไฟล์เก่าไม่ได้ ค่าเริ่มต้น Windows เก็บคีย์ตามบัญชีบริการที่รัน ASP.NET และอาจผูกการถอดรหัสกับ Windows account จึงต้องสำรองตามวิธีติดตั้งจริง ไฟล์ ZIP ไม่ได้เข้ารหัสเนื้อหา ต้องจัดเก็บเป็นข้อมูลลับ

## กู้คืนเมื่อสมัครใหม่ / ต่ออายุ

สร้างหรือเตรียมบัญชี Lawyer ปลายทางให้เรียบร้อย ตั้งแพ็กเกจและโควต้าที่ได้รับจากการต่ออายุ แล้วกด **กู้คืนทนายจาก ZIP** → เลือกไฟล์ → ตรวจสอบข้อมูลต้นทาง → เลือกบัญชีปลายทางและตรวจชื่อ/เลขใบอนุญาต → ยืนยัน

- ปลายทางต้องไม่มีคดีหรือเอกสารส่วนตัว ไม่เขียนทับหรือรวมเข้ากับคดีที่มีอยู่
- บัญชีต้นทางต้องถูกลบก่อนนำไปบัญชีใหม่ และคดีต้นทางต้องไม่อยู่หรือเคยกู้คืนแล้ว
- สร้างรหัสแถวใหม่และเชื่อมความสัมพันธ์ทั้งหมดในธุรกรรมเดียว หากเกิดข้อผิดพลาดจะไม่บันทึกบางส่วน
- กู้คืนข้อมูลติดต่อและประวัติทนาย แต่คง username/password บทบาท สถานะ และแพ็กเกจปัจจุบันของบัญชีปลายทาง ยอดใช้เครดิตเป็นค่าที่มากกว่าระหว่างปัจจุบันและประวัติเดิม ไม่คืนเครดิตจากการลบ/กู้คืน
- คงบัญชีและรหัสผ่านลูกความเดิมโดยจับคู่เลขประชาชน หากไม่มีบัญชีเลขนั้นแล้วจะสร้างบัญชีพร้อมรหัสเริ่มต้นและบังคับเปลี่ยนรหัส บัญชีเก่าที่ไม่มีเลขประชาชนต้องให้ทนายยืนยันเลขก่อนเข้าใช้งานหากต้องสร้างใหม่
- สิทธิ์เสมียนที่ยังมีบัญชีอยู่จะกลับมาในสถานะปิด ต้องตรวจสอบก่อนเปิดใช้งาน หากไม่มีบัญชีเสมียนแล้วจะไม่สร้างบัญชีเสมียนขึ้นเอง
- ปิดเซสชันทนายปลายทางเมื่อเสร็จ ให้เข้าสู่ระบบใหม่ และบันทึก audit สำหรับการสำรอง ลบ และกู้คืน
- ZIP สูงสุด 2 GB, ไฟล์แต่ละรายการสูงสุด 1 GB และ JSON สูงสุด 512 MB; IIS อนุญาต 2 GiB + 1 MiB สำหรับ multipart/restore
- ข้อมูลไฟล์ที่กู้คืนจะถูกเขียนกลับ `App_Data/Uploads`; สำรองพื้นที่จัดเก็บนี้ควบคู่กับ SQL Server

## ตรวจสอบ

`dotnet run --project scripts/LawyerArchiveIntegration/LawyerArchiveIntegration.csproj` ใช้ fixture ที่ล้างเมื่อเสร็จ ทดสอบ API จริงพร้อมฐานข้อมูล ตั้งแต่ backup → stale/tamper rejection → delete → restore → duplicate rejection รวมไฟล์และลูกความที่มีคดีร่วมหลายทนาย

`scripts/lawyer-archive-smoke.mjs` ทดสอบ UI ด้วย Playwright และ API จำลอง ครอบคลุมดาวน์โหลด ยืนยันลบ ดูตัวอย่าง เลือกบัญชี และยืนยันกู้คืน
